# EV-ServiceDesk — Mobile (Flutter)

## Целевые платформы
**iOS (iPhone) и macOS (MacBook)** на первом этапе — не Android. Flutter
поддерживает оба нативно как first-class таргеты, переписывания не
потребуется, если Android понадобится позже — платформа просто добавляется
(`flutter create --platforms=android .`).

## Машина разработки
MacBook Pro M5 Pro (Apple Silicon, arm64) — Flutter/Xcode тулчейн полностью
поддерживает M-серию, известных проблем совместимости нет. Для сборки
понадобятся:
- **Xcode** (актуальная версия из App Store) — обязателен для iOS и macOS таргетов
- **CocoaPods** (`sudo gem install cocoapods` или через Homebrew) — управление нативными зависимостями iOS/macOS
- **Apple Developer аккаунт** — бесплатный личный достаточен для локальной отладки на устройстве; платный ($99/год) понадобится позже для push-уведомлений через APNs (Firebase Cloud Messaging на iOS работает поверх APNs) и публикации в TestFlight/App Store (Главы 20, 27, 28)

## ⚠️ Ограничение окружения сборки (эта сессия)
Каркас написан вручную (Flutter SDK недоступен в среде, где готовился
проект — нет доступа к серверам загрузки Google). Файлы валидны по структуре
и синтаксису, но **не запускались и не собирались** — в отличие от backend
и web, где сборка и тесты реально прогонялись. На вашем MacBook Flutter
доступен полностью — там проверка реальна и обязательна.

**Перед первым использованием на MacBook обязательно:**
```bash
flutter create --platforms=ios,macos .   # если папки ios/ и macos/ ещё не сгенерированы
flutter pub get
flutter analyze
flutter test
```
и устраните то, что покажет `analyze` (могут быть неточности версий пакетов
в pubspec.yaml — фиксировала по памяти, не по фактическому `pub` resolve).

## Структура
- `lib/main.dart` — точка входа (корень: онбординг или разделы по состоянию входа)
- `lib/app/` — состояние приложения (`AppState`, `AppScope`)
- `lib/data/` — модели по `docs/openapi.yaml`, интерфейс `ClientRepository`, `PrototypeRepository` (фикстуры, глава 7)
- `lib/screens/` — онбординг, «Авто», «Обучение», «Поддержка», «Новости»
- `lib/theme/`, `lib/ui/` — дизайн-система (глава 6), состояния загрузки/пусто/ошибка, панель «Демо»
- `test/` — дизайн-система, сценарии прототипа и правило 3-х кликов

Прототип и сценарии ревью — `docs/design/MOBILE_PROTOTYPE.md` (глава 7, ADR 0011).
Реальный API, авторизация, push — главы 18–20.
