| Термин | Определение |
|---|---|
| VIN | Идентификационный номер автомобиля (17 символов); привязка авто к аккаунту и автозаполнение марки/модели/комплектации. |
| Агрегат | Контролируемый узел/расходник авто (масло двигателя, масляный/воздушный/салонный фильтр, масло редуктора, фреон кондиционера); список расширяется через админ-панель. |
| Регламент ТО | Заданный администратором для модели авто интервал (пробег/время) до плановой замены агрегата; не «зашит» в код. |
| Статус «светофор» | Расчётное состояние агрегата по доле выработанного интервала регламента: зелёный — ниже порога «скоро менять», жёлтый — от него до порога «требуется замена» включительно, красный — выше; пороги задаёт администратор (по умолчанию 70% и 100%). «Неизвестно» — выработку нельзя рассчитать: замена агрегата ещё не фиксировалась или для модели авто нет регламента ТО. |
| Замена агрегата | Зафиксированная инженером или администратором установка нового агрегата (расходника): дата и пробег замены обнуляют выработку по регламенту. Не путать с прочей записью в истории ТО (осмотр, долив), которая выработку не меняет. |
| Цифровой паспорт автомобиля | Раздел клиентского приложения: интерактивная схема агрегатов, история ТО, статусы. |
| Тикет | Обращение клиента в поддержку: категория (Навигация/Звук/SIM-связь/Сбой приложения/Агрегаты-ТО), статус, история переписки. |
| Статус тикета | Отдельная от статуса агрегата величина: Новый → В работе → Ожидает вендора → Решено (`new`, `in_progress`, `waiting_vendor`, `resolved`). |
| Очередь тикетов | Новые тикеты (статус «Новый»), ещё не взятые инженером в работу. Инженер видит из очереди карточку тикета и авто клиента, но менять данные авто может только по тикету, взятому им в работу. |
| SLA | Норматив срока решения тикета: срок отсчитывается от создания тикета и зависит от его категории. Не путать с первичным ответом — его время измеряется, но срока не имеет. |
| Просроченный тикет | Тикет, не решённый к сроку SLA. Решённый тикет просроченным не считается; решённый позже срока учитывается в аналитике как «решён с просрочкой». |
| Первичный ответ | Первое сообщение сотрудника поддержки (инженера или администратора) в чате тикета; время до него — показатель качества поддержки. |
| Переоткрытие тикета | Возврат решённого тикета в работу инженером или администратором. Срок SLA при этом не продлевается. |
| Дерево решений | Пошаговый сценарий самопомощи по типовой ошибке: вопросы с вариантами ответа ведут клиента либо к решению («проблема решена»), либо к эскалации в тикет. Есть только у статей типа «устранение неполадок». |
| Эскалация в тикет | Переход клиента из дерева решений к созданию тикета, когда самопомощь не помогла. Тикет помечается статьёй и её версией, из которой пришёл клиент. |
| Тупик дерева решений | Шаг, с которого клиент не может прийти ни к решению, ни к эскалации, — в том числе замкнутый круг вопросов. Статью с тупиком опубликовать нельзя. |
| База знаний | Статьи/инструкции для клиента («Обучение») и готовые ответы для инженера. |
| Черновик статьи | Неопубликованная статья базы знаний; её видит только администратор. Клиент и инженер видят только опубликованные статьи. |
| Версия статьи | Номер опубликованной редакции статьи базы знаний. Новая версия появляется, когда меняется опубликованное содержание статьи; правки черновика версий не создают. Прошлые версии сохраняются для просмотра, но не восстанавливаются. |
| Прошивка | ПО мультимедийной системы авто; уведомления информационные, удалённая перепрошивка не выполняется. |
| Русификация | Услуга компании по адаптации мультимедиа на русский язык; после неё клиенту устанавливается приложение. |
| RBAC | Модель разграничения доступа по ролям на уровне API. |
| Роль | Клиент (`client`) / Инженер поддержки, оператор (`engineer`) / Администратор (`admin`). |
| Push-уведомление | Сообщение через Firebase Cloud Messaging (прошивка, ТО, новости/акции). |
| VIN-декодер | Внешний сервис/API определения марки/модели по VIN. |
| Восстановление авто | Повторное добавление клиентом своего ранее удалённого авто по тому же VIN: авто возвращается в аккаунт вместе с историей работ. Не путать со сменой владельца — новый владелец получает авто без истории прежнего. |
| Канбан-доска | Инструмент инженера: тикеты, сгруппированные по статусу/приоритету/SLA. |
| Остаток ресурса | Расчётное значение (км/дни) до порога замены агрегата. |
| Uptime | Доля времени доступности системы (цель — не менее 99.5%). |
| WCAG | Стандарт доступности; в ТЗ — контраст текста не менее 4.5:1. |
| MoSCoW | Метод приоритизации: Must / Should / Could / Won't have. |
| MVP | Минимально жизнеспособный набор функций первого релиза. |
| DoD | Definition of Done — согласованный критерий завершённости этапа/главы. |
