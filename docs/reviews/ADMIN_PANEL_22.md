# Глава 22 — Админ-панель. Отчёт проверки

Issue #90, ветка `feature/90-admin-panel`, ADR 0026 (grill-with-docs Q1–Q20), глоссарий v1.14, контракт 1.11.0.
Админ-панель (`web-admin`) переведена с фикстур главы 8 на реальный API; режим прототипа (без
`VITE_API_BASE_URL`) сохранён для демо и тестов.

## Шаги чек-листа
| Шаг | Статус | Где |
|---|---|---|
| Авторизация администратора | PASS | вход по телефону и паролю (`staffLogin`), только роль `admin` — инженеру и клиенту отказ и выход; общий вход сотрудника `StaffSessionGate` (`web-shared`, вынесен из кабинета инженера); access в памяти, refresh в `sessionStorage` (`ev-admin-refresh`); CSP сборки, `/v1` на том же origin |
| Конструктор регламентов ТО (CRUD, привязка к моделям авто) | PASS | пересмотр (новая версия, прежняя — в истории, номера версий по порядку — U-44), архивирование, справочник агрегатов, пороги «светофора» (общие для всех моделей, «% износа» — U-42), подсказка «Как у масла» для масляного фильтра (ADR 0009); модели — справочник миграции, выбор модели |
| Конструктор статей базы знаний и публикация новостей/прошивок | PASS | статьи: «Сохранить и опубликовать» у новой статьи и при правках (U-05, U-43), «Опубликовать изменения (версия N+1)» у опубликованной, история версий только для чтения; дерево решений: шаги по номеру и тексту (U-40), вариант — только к шагу этого дерева, один корень, дерево опубликованной статьи заблокировано (как backend). Публикации: новость, акция, прошивка; подтверждение с числом получателей и устройств (`audience-preview`, U-45), «Отменить нельзя»; лента со статистикой доставки, фильтры типа и модели; напоминания о ТО вручную не публикуются |
| Дашборд аналитики (интеграция с Analytics Service) | PASS | период 7/30/90 дней или свой, фильтры модели и категории (где их принимает операция), «Данные на ЧЧ:ММ», «Обновить», часы до 0,01 (как в API), при смене фильтров прежние цифры не показываются, «Модели по числу тикетов» с пояснением «на 10 авто» (U-41) |
| Управление пользователями и ролями | PASS | список с фильтрами роли и блокировки, поиск по телефону; создание инженера или администратора, пароль вводится или генерируется и показывается один раз; роль инженер ↔ администратор, блокировка/разблокировка, **сброс пароля** (контракт 1.11.0), `LAST_ADMIN` — понятный текст; своя учётная запись — только просмотр; нерешённые тикеты инженера с переназначением или возвратом в очередь, предупреждение при блокировке и смене роли |

## Найдено и исправлено по ходу
| # | Что | Исправление |
|---|---|---|
| 1 | Прототип разрешал вариант дерева «никуда», второй корень, правку дерева опубликованной статьи и удаление шага, на который ведут варианты — backend это отклоняет | прототип отвечает теми же кодами (`INVALID_NEXT_NODE`, `DECISION_TREE_ROOT_EXISTS`, `ARTICLE_PUBLISHED`, `DECISION_TREE_NODE_REFERENCED`, `DECISION_TREE_INVALID`); форма шага требует переход, «Корневой шаг» недоступен при существующем корне |
| 2 | Форма публикации предлагала тип «Регламент ТО» — backend отклоняет (`NOTIFICATION_TYPE_RESERVED`) | типы публикации — новость, акция, прошивка; подсказка «Напоминания о ТО отправляет система» |
| 3 | Дашборд округлял часы до 0,1 (0,93 ч → 0,9 ч) — ручная сверка с расчётом до 0,01 не сходилась бы | `formatHours` — до 0,01, как в API |
| 4 | Переключатель темы в шапке подписан «Тема» — совпадал с полем «Тема» публикации (для скринридера — два одинаковых поля) | подпись «Оформление» (и в кабинете инженера) |
| 5 | Список статей брал одну страницу (20) — на реальном API статьи дальше 20-й пропали бы; фильтр «Черновики» — по загруженной странице | все страницы, фильтр публикации — запросом к API |
| 6 | «Сохранить и опубликовать» новой статьи: итог терялся при переходе на адрес созданной статьи (редактор монтируется заново) | итог передаётся редактору по новому адресу и сбрасывается при уходе с него |
| 7 | Тесты Vitest иногда кликали по старой форме до её перемонтирования после публикации | ожидание признака новой формы перед действием |
| 8 | «Новый агрегат»: примеры «Тормозная жидкость», «brake_fluid» в placeholder выглядели как введённые значения (как U-18) | примеры — в подсказке под полем |

## Чек-лист проверки владельцем (роль администратора)
Запуск: `MOBILE=1 web-admin/scripts/admin_run.sh` (iOS Simulator загружен). Админ-панель —
http://127.0.0.1:5176; входы администратора и инженеров, номер и код клиента — в
`~/.config/ev-servicedesk/admin.local`. В мобильном приложении войти клиентом (номер и код из файла).

1. Войти инженером 2 — отказ «Админ-панель — только для администраторов…»; войти администратором.
2. «Регламенты ТО» → Zeekr 001 → «Салонный фильтр» → «Изменить»: 12 000 км. В приложении клиента —
   «Авто», потянуть вниз: салонный фильтр «жёлтый». Затем 9 000 → «красный»; вернуть 20 000 → «зелёный».
   «Показать историю версий» — прежние версии с номерами.
3. «Масляный фильтр» → «Изменить»: подсказка интервала масла, «Как у масла». Пороги — подписи понятны.
4. «База знаний» → «Новая статья» (инструкция) → «Сохранить и опубликовать»; в приложении — «Обучение».
   Открыть статью снова, поправить текст — кнопка «Опубликовать изменения», версия 2, «История версий».
5. Статья «Устранение неполадок»: вкладка «Дерево решений» заблокирована; «Снять с публикации» → добавить
   шаг с вариантом → «Проверить дерево» → удалить шаг → «Опубликовать».
6. «Публикации» → новость для Zeekr 001 → «Опубликовать…»: число получателей → «Опубликовать»; в
   приложении — новость в центре уведомлений; в ленте админ-панели — статистика.
7. Прошивка для Zeekr 001 (версия новее текущей) → подтверждение → уведомление о прошивке в приложении.
8. «Пользователи» → создать инженера («Сгенерировать», скопировать пароль) → выйти и войти им: отказ
   «только для администраторов» — значит, пароль верный; войти снова администратором.
9. Карточка инженера 1: переназначить его тикет инженеру 2; сбросить пароль; заблокировать (предупреждения в
   подтверждении). Своя учётная запись — только просмотр.
10. «Дашборд» → «Свой период» 01.03.2026–31.03.2026 → сверить с `docs/ANALYTICS_CONTROL.md` (разделы 2–4:
    A1, P1–P3, C1); модель «Контроль Бета» — A3 и C3.
11. «Оформление»: светлая и тёмная; окно Full HD — без горизонтальной прокрутки.

## Решения по ходу (ADR 0026, уточнения при реализации)
- `LAST_ADMIN` на стеке E2E не воспроизвести: вошедший администратор — уже второй активный; проверяют тесты
  backend (`test_last_admin_cannot_be_demoted_or_blocked`, гонка понижений) и Vitest карточки.
- Для прошивки число получателей до создания релиза не узнать (уведомление создаётся вместе с релизом) —
  в подтверждении оценка сверху: владельцы модели.
- Смена пароля самим сотрудником, дата и автор версии регламента, внутренние заметки статей, конструктор
  SLA и категорий, загрузка медиа статей, создание моделей авто — бэклог (ADR 0026, «Последствия»).
