## Чек-лист прогона на iPhone (владелец, 3 раза подряд в разных сессиях)
Стенд: `mobile/scripts/device_run.sh` — стек из образа-кандидата, статьи поддержки, приложение на iPhone. Номер и код
печатаются в Terminal (`Клиентский сценарий главы 20`). Инженер — меню в том же окне Terminal. Прогон с ошибкой
обнуляет серию.

1. **Вход.** Номер из Terminal, код, согласие ПД (1-й прогон) → «Войти». Без авто — добавить по VIN (подходит
   `L6TZ001` + 10 любых цифр, модель — Zeekr 001).
2. **Обучение.** «Обучение» → «Как обновить карты навигации»: заголовки и список без `#` и `**`, ссылка
   «сайте сервиса» открывает браузер.
3. **Дерево решений.** «Поддержка» → «Неполадки» → «Навигация не строит маршрут» → «Нет» → «Нет, не строится» →
   «Создать обращение».
4. **Тикет с фото.** Категория «Навигация» и ход диагностики подставлены → «Фото или видео» → «Сфотографировать»
   (или «Фото из галереи») → индикатор загрузки сменился значком фото → «Отправить». Открылся чат: первым
   сообщением — описание и фото; фото открывается на весь экран.
5. **Ответ инженера.** В Terminal ввести номер обращения из заголовка чата → Enter. В чате без обновления
   появился ответ «Инженер поддержки», статус — «В работе».
6. **Ответ клиента.** Написать сообщение, прикрепить видео (≤ 200 МБ) → «Отправить» → сообщение с видео в чате;
   видео открывается в плеере.
7. **Свернуть и вернуться.** Свернуть приложение, в Terminal — ещё раз номер обращения, вернуться в приложение:
   новый ответ на месте, надписи «переподключаемся» нет.
8. **Решение.** В Terminal `r <номер>` → в чате статус «Решено», поле ввода сменилось надписью «Обращение решено».
9. **Новости и центр уведомлений.** В Terminal `n` → колокольчик в шапке со счётчиком → центр уведомлений:
   новость и акция → открыть новость → счётчик уменьшился; вкладка «Новости» — новость и акция, прошивок и ТО нет.
10. **Выход.** «Авто» → профиль → «Выйти».

## Push на Android-эмуляторе (настоящий FCM)
Один раз: владелец создаёт проект Firebase (Spark) с Android-приложением `com.etsavtogomel.evServicedesk` и
запускает `scripts/firebase_dev_setup.sh`. Стенд: `mobile/scripts/android_push_run.sh` — эмулятор с Google Play,
стек с настоящим FCM, debug-сборка с `FIREBASE_*`.

|---|---|---|

## Решения по ходу (ADR 0024)
- Проверка в iOS Simulator нашла: `firebase_messaging` 15.x подключает делегат уведомлений по
  `UIApplicationDidFinishLaunchingNotification`, а шаблон Flutter 3.47 (UIScene, неявный движок) регистрирует
  плагины позже — нажатие на push терялось. Обновлено до `firebase_messaging` 16.7.0 / `firebase_core` 4.15.0
  (поддержка UIScene, Firebase iOS SDK 12).
- Кнопка «Открыть» на баннере push была тёмной на тёмном (Material 3 красит действие SnackBar в
  `inversePrimary`, он не задан) — тема SnackBar из токенов, тест контраста ≥ 4,5.
- Без FCM-токена (iOS без APNs) нажатие на push всё равно открывает уведомление — `markOpened` больше не
  бросает исключение (регрессионный тест).
- Backend не создаёт первое сообщение из описания тикета: описание и вложения — в карточке (`TicketDetail`).
  Чат показывает их первым сообщением клиента; прототип приведён к тому же поведению (нашёл `test_api_e2e`).
- Повторный 4401 подряд — уже с паузой: без неё клиент с отклонённым токеном переподключался бы без конца
  (нашёл `ticket_live_test`).
- Для сценария главы 20 — свой тестовый номер `+375290009004` (`E2E_SUPPORT_PHONE`): лимит запросов кода на номер.
- Ответ инженера на устройстве — меню в Terminal (`mobile/scripts/staff_menu.sh`) вместо отдельного скрипта:
  стек и инженер в одном окне.
