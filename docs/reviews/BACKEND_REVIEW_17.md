# Ревью backend главы 17: дублирование логики и рассинхронизация контрактов

Глава 17 `MASTER_CHECKLIST.md`, шаг «Код-ревью всех сервисов на дублирование логики и
рассинхронизацию контрактов»; порядок — ADR 0021 п. 11. Дата: 2026-10-12, ветка
`feature/72-backend-integration` (Issue #72).

**Как проводилось.** Два независимых прохода только на чтение по всем модулям `backend/app`
(auth, users, vehicles, aggregates, tickets, knowledge, notifications, analytics, workers, tools):
1. дублирование и расхождение одних и тех же правил между модулями;
2. текст `docs/openapi.yaml` и `docs/asyncapi.yaml` против кода: коды ошибок, параметры, описания,
   версии.

Каждая находка проверена чтением обеих сторон. Отдельно работает автоматическая проверка:
`ContractClient` сверяет каждый ответ всего набора API-тестов со схемой контракта (ADR 0021 п. 2).
Она сама нашла одно расхождение — C0 ниже.

Правило: мелкое исправляется в PR главы, крупное выносится в issues — #73 (рефакторинг) и
#74 (схемы контракта).

## Дублирование и расхождение правил (D)

| # | Серьёзность | Находка | Итог |
|---|---|---|---|
| D1 | high | `POST /vehicles` с `vehicle_model_id = 2**63` → ошибка БД и 500; остальные модули проверяют диапазон BIGINT | **исправлено**: `get_by_id`, тест на `10**9` и `2**63` |
| D2 | high | Push-токен регистрировался без действующего согласия ПД (после отзыва access-токен живёт до 15 мин), а аудит считает такой токен нарушением | **исправлено**: проверка `eligible_client` под блокировкой пользователя → `422 PD_CONSENT_REQUIRED` (контракт 1.7.1), тест |
| D3 | high (не проявлялось) | Вход по SMS и паролю проверял `is_active`, все остальные проверки — `is_available` (активен и не анонимизирован) | **исправлено**: вход проверяет `is_available`, тест |
| D4 | medium | Push по тикету отправлялся без перехвата сбоя отправителя, в отличие от очереди доставок | **исправлено**: общий `dispatch.send_safely` |
| D5 | medium | Исполнитель тикета: `assign` разрешает только инженера, а повышение engineer → admin оставляет тикеты за администратором | **решено** (ADR 0021, уточнения): назначенный администратор допустим; аудит запрещает только клиента |
| D6 | medium | Предикат «неудалённое авто владельца» повторён 7 раз (сейчас согласован) | **issue #73** |
| D7 | medium | «Сегодня по Минску» жил в Aggregates, Vehicle считал его сам | **исправлено**: `core.time.today_in_business_tz` |
| D8 | medium | Напоминания повторяют арифметику расчёта статуса агрегата | **issue #73** |
| D9 | medium | Python-копия правила просрочки SLA, которую проверяли только тесты; API работает по SQL-выражению | **исправлено**: копия и её тест удалены, границы проверяет `test_overdue_boundary_is_strict` через БД |
| D10 | low | Отзыв «все сессии» и множество ролей персонала определены в нескольких местах | **исправлено**: `auth.service.end_all_sessions`, `models.enums.STAFF_ROLES` |
| D11 | low | Конструктор ошибки поля 422 скопирован в 4 модуля и ещё 5 раз собран вручную | **исправлено**: `core.errors.field_error` |
| D12 | low | Заготовка worker'ов: advisory lock и сигналы повторены, остановка устроена по-разному | **issue #73** |
| D13 | low | Тестовые хелперы повторяются; 174 ручных вызова `assert_contract` дублируют `ContractClient` | ручные вызовы **удалены**; остальное — **issue #73** |

**Проверено, расхождений нет:**
- `eligible_client` — единственный источник правила для аудитории, напоминаний, отправки и push по тикету;
- `AppUser.is_available` совпадает с SQL аудита;
- видимость тикета клиенту совпадает с видимостью авто;
- правила пробега между Vehicle и Aggregates различаются намеренно (ADR 0016);
- «светофор» считает одна функция;
- пагинация и экранирование LIKE реализованы в одном месте;
- 404 для id вне диапазона единообразен в модулях доступа.
