# 0011. Кликабельный прототип клиента — на Flutter с фикстурами, а не в Figma

**Статус:** Принято, 2026-10-10 (владелец проекта, Issue #37)

## Контекст
Глава 7 требует кликабельный прототип всех ключевых экранов клиента: онбординг (телефон → SMS-код → авто
по VIN), главный экран с переключателем авто и интерактивной схемой агрегатов, карточка агрегата,
«Обучение», «Устранение неполадок», «Тикеты/Чат», «Уведомления», несколько авто, пустые состояния и
ошибки; проверка правила 3-х кликов (ТЗ, раздел 6). ТЗ (раздел «Эргономическое проектирование»)
предполагает прототипы в Figma. Figma — тариф Starter (ADR 0010): 3 страницы, лимит вызовов MCP,
без публикации библиотеки. Flutter-клиент уже содержит тему на токенах и компоненты главы 6.

Нижняя навигация главы 6 (`EvBottomNav`) — 5 пунктов; подпись «Уведомления» не помещается в ячейку при
360–390 px (открытый вопрос `docs/design/DESIGN_SYSTEM.md`). ТЗ, раздел 9: «Авто» / «Обучение» /
«Поддержка» / «Новости».

## Варианты
- **Носитель прототипа:** Figma (клик-прототип) / Flutter на фикстурах / Figma после Education + Flutter.
- **Данные:** Prism mock по `docs/openapi.yaml` (сеть, Docker) / фикстуры в приложении за интерфейсом
  репозитория.
- **Навигация:** 5 пунктов (как в главе 6) / 4 пункта по ТЗ.

## Решение
1. **Вариант A — Flutter** (iOS Simulator, macOS): прототип — это клиент главы 18 без сети. Доступ к
   данным — интерфейс `ClientRepository` (операции OpenAPI v1); в прототипе — `PrototypeRepository`
   на фикстурах в памяти, в главе 18 — реализация на HTTP без изменения экранов. Модели
   (`lib/data/models.dart`) — подмножество схем контракта с теми же именами полей.
2. **Фикстуры, а не Prism:** прототип запускается без Docker и сети и детерминирован в тестах;
   сценарии ревью (нет сети, без авто / одно / несколько авто, тема, выход к онбордингу) переключаются
   в панели «Демо» (иконка с ползунками в шапке, только для `PrototypeRepository`).
3. **Навигация по ТЗ — 4 пункта:** «Авто» / «Обучение» / «Поддержка» / «Новости». «Устранение
   неполадок» и «Тикеты/Чат» — вкладки «Поддержки»; «Уведомления» — лента «Новости» (в контракте одна
   коллекция `/notifications` с типами `firmware|maintenance|news|promo`), счётчик непрочитанных — на
   пункте навигации. Закрывает открытый вопрос главы 6 о подписи «Уведомления».
4. **Правило 3-х кликов проверяется автотестами** (`mobile/test/prototype_test.dart`) — счётчик тапов от
   главного экрана; таблица сценариев — `docs/design/MOBILE_PROTOTYPE.md`.
5. **Figma-прототип не делается в главе 7.** После перехода на Education ключевые экраны можно перенести
   в Figma по скриншотам `docs/design/prototype/` (не входит в DoD).

## Последствия
- Отступление от ТЗ («прототипы в Figma»): утверждение прототипа — ревью сборки в симуляторе или на
  устройстве владельцем/руководителем (DoD главы 7), а не ссылка на Figma.
- Экраны прототипа — основа глав 18–20; при подключении API меняется реализация репозитория,
  авторизация (JWT, глава 18), вложения через `/uploads/presign` (глава 15), чат в реальном времени
  (глава 17), push (глава 20).
- Тема дополнена вкладками и чипами (`evTheme`): брендовый жёлтый — только заливка с `on-primary`, текст
  активной вкладки — `fg`, подчёркивание — `primary-text` (жёлтый текст на белом — 1.5:1).
