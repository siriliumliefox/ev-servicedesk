# 0022. Мобильный клиент: HTTP-репозиторий вместо фикстур, refresh одним запросом без повторов, E2E на уровне API в CI и UI локально, Android только сборкой

**Статус:** Принято, 2026-10-12 (владелец проекта, Issue #76, grill-with-docs Q1–Q15; рекомендации
приняты по правилу владельца от 2026-10-12)

## Контекст
Глава 18 переводит клиентское приложение с прототипа на реальный backend: онбординг и вход
(Auth Service), secure storage и автообновление токенов, добавление авто по VIN, главный экран
с переключателем авто, карточка авто с историей ТО (Vehicle Service). Проверка в чек-листе —
E2E на Detox/Appium и тест на соединении 2G; DoD — «собирается под iOS и Android, базовый флоу
проверен на реальном устройстве». Факты на начало главы:
- `mobile/` — кликабельный прототип главы 7 (ADR 0011): экраны работают через `ClientRepository`,
  данные — `PrototypeRepository` на фикстурах; ADR 0011 предусматривает HTTP-реализацию без
  изменения экранов; платформы — iOS и macOS, Android нет, Android SDK локально без cmdline-tools;
- `flutter_secure_storage` подключён, но не используется; шрифт Inter отложен до главы 18 (ADR 0010);
- backend (глава 17, тег `backend-v1.0-beta`) реализует все операции `ClientRepository`;
  ротация refresh с обнаружением повтора: повторно предъявленный refresh **отзывает все сессии**
  пользователя; access — 15 мин, refresh — 30 дней;
- платного Apple Developer нет, Android-устройства нет (ADR 0019 п. 20); staging-сервера нет до
  главы 26 (ADR 0008); стек `compose --profile full` и `SMS_TEST_PHONES` — глава 17 (ADR 0021);
- Detox — инструмент React Native, Appium для Flutter требует отдельного драйвера; у Flutter есть
  официальный `integration_test`.

## Варианты
- **Платформы:** добавить Android и собирать в CI / записать отказ от Android в DoD.
- **E2E:** Detox/Appium / Patrol / `integration_test` в симуляторе / Dart-тест репозитория против
  стека backend.
- **Объём HTTP:** только Auth и Vehicle, остальное на фикстурах / все операции `ClientRepository`.
- **Повтор refresh:** grace-период на backend / идемпотентный refresh / клиент не повторяет refresh.
- **Хранение:** access и refresh в Keychain / только refresh, access в памяти.
- **Конфигурация:** только HTTP / прототип без `API_BASE_URL`, HTTP — с ним.

## Решение
1. **Платформы (Q1).** Добавлена платформа Android (`com.etsavtogomel.evServicedesk`, minSdk 23).
   CI собирает `flutter build apk --debug` (ubuntu) и `flutter build ios --no-codesign`
   (macos-latest) при изменениях `mobile/`. Реальное устройство — iPhone; Android проверяется
   только сборкой (устройства нет). macOS остаётся платформой разработки вне DoD.
2. **E2E (Q2, Q14).** Два уровня вместо Detox/Appium:
   - `api_e2e` — Dart-тест настоящего `HttpClientRepository` против стека `compose --profile full`
     из образа-кандидата (как ADR 0021): регистрация по SMS (`SMS_TEST_PHONES`) → согласие ПД →
     авто по VIN → список → карточка → пробег → история работ → refresh → выход. Job
     `mobile / api-e2e` в `mobile-ci.yml`, при изменениях `mobile/` или `backend/`, входит в `ci-gate`;
   - UI E2E — `integration_test` в iOS Simulator против локального стека
     (`mobile/scripts/e2e_ui.sh`), результат — в отчёте главы: на macOS-раннерах GitHub нет Docker.
3. **Плохая сеть (Q3).** Автотесты с подменённым транспортом (задержка, обрыв, тайм-аут, 5xx):
   индикатор загрузки, понятная ошибка, «Повторить», сессия не завершается. Тайм-аут запроса —
   20 с. Ручной прогон в симуляторе с Network Link Conditioner (профиль Edge) — в отчёте.
4. **Реальное устройство (Q4).** Бесплатная подпись Personal Team в Xcode; iPhone ходит в
   локальный стек по `http://<mac>.local:8000` (`NSAllowsLocalNetworking`, на production не
   распространяется). Прогон делает владелец; до него глава — PARTIAL.
5. **Объём HTTP (Q5).** Через HTTP — все операции `ClientRepository`: иначе настоящий пользователь
   видит выдуманные тикеты и новости. Глубокие функции — своим главам: вложения тикета
   (presign → S3) и WebSocket-чат — 20 (кнопка вложений в HTTP-режиме скрыта), push — 20/27,
   интерактивная схема агрегатов — 19.
6. **Refresh (Q6).** Backend не меняется — ослаблять обнаружение кражи токена ради клиента нельзя.
   Клиент: на все параллельные 401 — один запрос refresh, повтор исходного запроса один раз;
   запрос refresh автоматически не повторяется. **Принятый риск:** если ответ refresh потерян
   (обрыв после ротации на сервере), следующая попытка предъявит старый токен — backend завершит
   все сессии пользователя, клиент увидит «Сессия завершена, войдите снова».
7. **Хранение (Q7).** В `flutter_secure_storage` — только refresh-токен (iOS —
   `first_unlock_this_device`, без iCloud); access — в памяти. Keychain переживает удаление
   приложения, поэтому при первом запуске после установки хранилище очищается (метка в
   `shared_preferences`). macOS — entitlement `keychain-access-groups`.
8. **Конфигурация (Q8).** `--dart-define=API_BASE_URL=…` — HTTP; без него — `PrototypeRepository`
   с панелью «Демо» (юзабилити, демонстрации). Новых пакетов для HTTP и состояния нет (`http`,
   `ChangeNotifier`); добавлены `shared_preferences` и `integration_test` (SDK).
9. **Шрифт (Q9).** Inter подключён ассетом (OFL, лицензия рядом), `layout_real_font_test`
   проверяет 360 px с ним.
10. **Запуск без сети (Q10).** Есть refresh, нет сети — главный экран в состоянии «Нет сети» с
    «Повторить». На онбординг ведут только 401 от refresh и `ACCOUNT_DISABLED`.
11. **Профиль (Q11).** Телефон, «Выйти» (`POST /auth/logout` best effort, хранилище очищается
    всегда), «Отозвать согласие» (`DELETE /auth/pd-consent`, с подтверждением, 99-З ст. 10).
    Текст политики — заглушка редакции `2026-10`, юридический текст — глава 25.
12. **Ошибки (Q12).** Одна таблица «код контракта → текст»: `CODE_INVALID` с числом попыток,
    `RATE_LIMITED` с отсчётом `Retry-After`, `VIN_*`, `MILEAGE_DECREASE`, `PD_CONSENT_REQUIRED` →
    согласие; неизвестный код — общий текст, `message` сервера не показывается. POST при ошибке
    сети автоматически не повторяется.
13. **Пробег (Q13).** Ввод пробега в карточке авто; история работ — постранично.
14. **Глоссарий (Q15).** «Сессия» — v1.10.

## Последствия
- Экраны прототипа не переписываются: меняются источник данных и состояния загрузки/ошибки.
- Прототип остаётся рабочим режимом сборки без `API_BASE_URL`; тесты прототипа сохраняются.
- CI дороже: сборка iOS на macos-latest и стек backend в `mobile / api-e2e`; запускаются только
  при изменениях соответствующих путей.
- Потеря ответа refresh на плохой сети завершает все сессии пользователя (п. 6) — пересмотреть,
  если бета-пилот (гл. 27) покажет частые повторные входы.
- Проверка на реальном iPhone — действие владельца; Android на устройстве не проверяется.
