# 0005. Секреты авторизации и персональные данные (X-04, N-06, N-07, N-08)

**Статус:** Принято, 2026-10-08 (владелец проекта, Issue #8). Хранение согласия (п. 4) заменено ADR 0006.

## Контекст
OpenAPI содержит вход по SMS-коду, `/auth/refresh` и `/auth/logout`, но исходная схема не имела
места для кодов и refresh-токенов. VIN и телефон — персональные данные (N-07).

## Варианты
- **SMS-коды:** таблица в PostgreSQL / Redis с TTL.
- **Refresh-токены:** stateless JWT без отзыва / хранение хэша в PostgreSQL.
- **ПД:** шифрование колонок (pgcrypto + blind index) / хранение открыто с организационными мерами.

## Решение
1. **SMS-коды — только Redis**: ключ по телефону, значение — HMAC-SHA256(код, секрет из env),
   TTL и счётчик попыток (rate limit N-06). В PostgreSQL кодов нет; в логах код не пишется.
   Реализация и тесты — Глава 10.
2. **Refresh-токены — таблица `refresh_token`**: только SHA-256 токена (`token_hash`, CHECK —
   64 hex-символа, UNIQUE), `expires_at`, `revoked_at`; logout/ротация = `revoked_at`.
3. **Пароли персонала** — `app_user.password_hash` (argon2/bcrypt, N-08); CHECK: для `engineer`/`admin`
   обязателен.
4. **ПД на MVP хранятся открыто** с мерами: телефон в E.164 (CHECK), согласие
   история согласий `pd_consent` (ADR 0006; было `pd_consent_at` + `pd_policy_version`), анонимизация `anonymized_at` (телефон обнуляется,
   история сохраняется), физическое удаление пользователя с данными запрещено (RESTRICT),
   маскирование VIN/телефона в логах, доступ по RBAC + object-level.

## Последствия
- ASSUMPTION: соответствие Закону РБ № 99-З «О защите персональных данных» юридически не
  проверено; текст согласия и сроки хранения — до бета-пилота (Глава 27). Трассировка требований
  закона и открытые пункты — [`docs/compliance/PD_99Z_CHECKLIST.md`](../compliance/PD_99Z_CHECKLIST.md).
- Шифрование на уровне диска/бэкапов — Глава 26; переход на шифрование колонок —
  отдельный ADR при необходимости.
- Анонимизация VIN (неизменяем триггером) потребует контролируемого исключения в триггере
  (техдолг).
