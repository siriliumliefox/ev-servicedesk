# 0014. Vehicle Service: мок VIN-декодера, конфликт VIN, доступ инженера, история работ

**Статус:** Принято, 2026-10-11 (владелец проекта, Issue #50, grilling — раунды 1–2). Развивает
ADR 0003 (п. 5), ADR 0006 (п. 1), ADR 0013.

## Контекст
Глава 11 требует CRUD авто по VIN с привязкой к клиенту, интеграцию или мок VIN-декодера,
историю работ (заполняют инженер/админ), несколько авто на аккаунт, монотонный пробег, тест
конфликта «один VIN на двух аккаунтах» и DoD «на staging, контрактные тесты с Auth Service».
Контракт v1 заморожен (ADR 0007); сервиса тикетов ещё нет (Глава 13), но таблица `ticket`
с `vehicle_id` и `assigned_engineer_id` есть (Глава 2). Справочник `vehicle_model` пуст.
VIN — персональные данные (ADR 0005).

## Варианты
- **Декодер:** внешний API (NHTSA vPIC) / мок в БД / мок в коде.
- **Повтор VIN:** один код 409 / два кода; своё удалённое авто — новая запись / восстановление.
- **Доступ инженера:** только назначенные тикеты / плюс очередь `new` / все авто.
- **Контрольная цифра VIN:** проверять / не проверять.
- **Строчные буквы VIN:** нормализовать на сервере / 422 по контракту.
- **Перебор VIN:** без лимита / лимит попыток на пользователя.

## Решение
1. **Мок VIN-декодера в коде** за интерфейсом `VinDecoder` (seam — зависимость
   `get_vin_decoder`). Внешний API отклонён: vPIC плохо знает китайские электромобили и
   передавал бы VIN (ПД) за рубеж. Таблица: префикс VIN → марка/модель, самый длинный
   совпавший префикс. WMI Zeekr `L6T` подтверждён письмом Zeekr в NHTSA (49 CFR 565, 2026);
   **ASSUMPTION:** символы 4–8 записи `L6TZ001` — демонстрационные, не из реестра производителя.
   WMI Li Auto и Voyah в открытых источниках не подтверждены — их VIN мок не распознаёт:
   `422 VIN_DECODE_FAILED`, клиент выбирает модель (`GET /vehicle-models`). Справочник моделей —
   миграция `0006`: Zeekr 001, Voyah Free, Li Auto L7 (без комплектации).
2. **Конфликт VIN.** Активный VIN на другом аккаунте → `409 VIN_REGISTERED_TO_ANOTHER_ACCOUNT`
   (владелец, телефон и id авто не раскрываются, `details = null`); на своём →
   `409 VIN_ALREADY_ADDED`. Своё удалённое авто с тем же VIN **восстанавливается** (снимается
   `deleted_at`, тот же id, история работ сохраняется); `vehicle_model_id` запроса при этом не
   применяется (модель неизменяема). Смена владельца — только после удаления авто прежним
   владельцем или через поддержку (Глава 13); новая запись не видит историю прежнего (ADR 0003).
   Гонка «проверка → вставка» закрыта `uq_vehicle_vin_active`: проигравший получает тот же 409.
3. **Лимит `POST /vehicles`:** 10 попыток в час на пользователя (`VEHICLE_CREATE_PER_USER_HOUR`),
   считаются и неуспешные (иначе 409 — оракул «зарегистрирован ли VIN»); превышение →
   `429 RATE_LIMITED` + `Retry-After`. В контракт добавлен ответ 429 (OpenAPI 1.3.0, без
   ломающих изменений — `oasdiff`).
4. **Object-level доступ** (`app/domain/vehicles/access.py`, одна точка для всех маршрутов):
   - client — свои активные авто; удалённое и чужое → 404;
   - engineer — просмотр: авто из тикетов, назначенных на него (любой статус), и из
     неназначенных тикетов `new` (очередь: карточка до «взять в работу», прототип главы 8);
     изменение (пробег, история работ) — только по своему тикету не в `resolved`, иначе 403;
     без тикета → 404. Удалённое авто по тикету видно (`is_active = false`);
   - admin — любое авто, в т. ч. удалённое.
   Удаление авто с активным тикетом разрешено (у `DELETE` в контракте нет 409); тикет остаётся.
5. **История работ:** `mileage_at_service` выше текущего пробега поднимает пробег авто в той же
   транзакции; записи задним числом (ниже текущего) допустимы и пробег не меняют;
   `performed_at` позже сегодняшней даты по `Europe/Minsk` → `422 PERFORMED_AT_IN_FUTURE`;
   нет ни агрегата, ни описания → `422 MAINTENANCE_SUBJECT_REQUIRED`; неизвестный код агрегата →
   `422 AGGREGATE_TYPE_NOT_FOUND`. `ticket_id` заполняется автоматически: у инженера — последний
   созданный его тикет по авто не в `resolved`, у админа — `null` (связь «обращение → ТО», A-06).
   Сброс счётчика агрегата — Глава 12.
6. **VIN:** только длина 17 и алфавит без I, O, Q (как `vin_format` в БД и шаблон контракта);
   контрольная цифра не проверяется — она не обязательна для VIN из ЕС. Строчные буквы и
   пробелы → 422 по контракту; верхний регистр — задача клиента (Глава 16). Значение VIN в
   ответ об ошибке не возвращается.
7. **Пробег:** уменьшение → `409 MILEAGE_DECREASE` (`details.current_mileage`); исправление вниз —
   только admin через журнал (ADR 0006): `409 MILEAGE_CORRECTION_STALE` /
   `409 MILEAGE_NOT_DECREASED`.
8. **«На staging»** — как ADR 0013: образ `backend:staging` публикуется после smoke-теста;
   smoke дополнен операциями Vehicle в Swagger и 401 без токена на `/v1/vehicles`.

## Последствия
- Миграция `0006` (данные); downgrade удаляет модели, если на них не ссылаются авто (FK RESTRICT).
- OpenAPI 1.3.0: 429 у `createVehicle`, коды ошибок в описаниях операций Vehicle.
- Пагинация коллекций — общий модуль `app/api/pagination.py` (для глав 12–15).
- `UserPublic.performed_by` в истории работ по контракту отдаёт клиенту телефон сотрудника —
  открытый вопрос ПД (99-З) на Главу 25; контракт v1 не меняется.
- Подключение настоящего декодера (X-05, Should) — новая реализация `VinDecoder` без изменения
  схемы БД и контракта.
