# 0035. Контракт v1: лимиты сервера — описаниями полей с тестом, 422 повтора версии прошивки остаётся, 403 у getTicket убран

**Статус:** Принято, 2026-10-19 (Issue #74, находки C8, C15, C16 ревью главы 17
`docs/reviews/BACKEND_REVIEW_17.md`; решения — рекомендации агента, приняты по правилу владельца
2026-10-12)

## Контекст
Ревью главы 17 нашло расхождения схем контракта с сервером, которые в 1.7.1 не исправлялись: правки
схем oasdiff считает ломающими, а контракт v1 заморожен (ADR 0007: допустимы только новые значения
ENUM в ответах). Проверка oasdiff 1.32.1 на копии контракта (2026-10-19):
- новый `maxLength`/`minLength` у поля запроса и уменьшение `maxLength` — **ошибка** (request-property-
  max-length-set, …-min-length-set, …-max-length-decreased);
- удаление ответа 403 у операции — **не ломающее**.

## Варианты
- **C8** (`createFirmwareRelease`: повтор версии — 422 `FIRMWARE_VERSION_EXISTS`, у агрегата — 409
  `AGGREGATE_TYPE_EXISTS`): перейти на 409 / оставить 422.
- **C15** (лимиты сервера без `maxLength` в схеме; `token` — 4096 в схеме против 1024 на сервере):
  `maxLength` в схемах с записью в `docs/api-breaking-allowed.txt` / поднять лимит сервера до схемы /
  описания полей и тест.
- **C16** (`getTicket` объявляет 403, которого нет): оставить / убрать.

## Решение
1. **C8 — 422 остаётся.** Смена кода сломала бы клиентов, обрабатывающих 422; повтор версии — ошибка
   поля `version` (админ-панель показывает её у поля), а повтор кода агрегата — конфликт сущности
   (409). Оба кода описаны в контракте. Прототип `web-shared` отвечал на оба случая общим
   `CONFLICT` 409 — приведён к кодам сервера (`FIRMWARE_VERSION_EXISTS` 422 по `version`,
   `AGGREGATE_TYPE_EXISTS` 409).
2. **C15 — лимиты описаниями.** Схема не меняется; в описаниях полей — граница сервера:
   `searchVehicleModels.search` ≤ 100, `PresignRequest.file_name` 1–255, путь `aggregateTypeCode`
   ≤ 50, `StaffLoginRequest.password` ≤ 256, `PushTokenRegisterRequest.token` ≤ 1024 (при
   `maxLength: 4096` схемы), `AggregateReplaceRequest.description` ≤ 255 (с 1.7.1). Поднимать лимит
   токена до 4096 нельзя: по колонке — частичный уникальный индекс B-tree `uq_push_token_token_active`,
   а он не примет такую строку (предел записи индекса ≈ 2,7 КБ); токены FCM — около 200 символов. `backend/tests/api/test_contract_limits.py`
   сверяет описание с сервером: на границе — не ошибка длины, за ней — 422 по полю.
3. **C16 — 403 у `getTicket` убран:** роли — все три, невидимый тикет — 404 (ADR 0017 п. 6).
   403 по роли у операций с ограниченными ролями проверяет автотест RBAC главы 25.
4. Контракт 1.17.0, `oasdiff` — без ломающих.

## Последствия
- Разработчик интеграции знает лимиты из контракта, а рассинхронизацию описания и сервера ловит тест.
- Схемы v2 (после заморозки v1) могут перенести лимиты в `maxLength` — описания станут лишними.
