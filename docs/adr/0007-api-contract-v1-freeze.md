# 0007. Контракт API v1: заморозка, правила и проверки

**Статус:** Принято, 2026-10-10 (владелец проекта, Issue #18)

## Контекст
Глава 3 требует заморозить контракты всех сервисов (v1) и поднять mock-сервер для параллельной
разработки клиентов. На момент аудита `docs/openapi.yaml` 1.0.0-rc3 был валиден, но: пагинация была
у 5 из 13 коллекций, не было эндпоинтов пользователей (A-04), профиля и аналитики (A-05, A-06),
ответы ошибок объявлялись непоследовательно (часть защищённых операций без `401`/`403`/`404`),
роли не сверялись с RBAC-матрицей, не было линтера, mock-сервера и контроля ломающих изменений.

## Варианты
- **Аналитика:** в v1 / отдельным добавлением в v1.1.
- **Пагинация:** только у больших коллекций / у всех.
- **Контроль контракта:** ручное ревью / линтер + тесты + diff ломающих изменений в CI.
- **Mock:** Prism по OpenAPI / ручные заглушки.

## Решение
1. **Версия `1.0.0` заморожена.** Аналитика (`/analytics/*`), пользователи (`/users`, `/me`) входят в v1.
2. **Все коллекции пагинированы** единообразно: `page`/`page_size` (1…100) и ответ
   `{items, meta: PaginationMeta}`. Голый массив в ответе запрещён.
3. **Единые ответы ошибок** через `#/components/responses` (схема `Error`); обязательны: `default`;
   `401` — у защищённых; `403` — если доступно не всем ролям; `404` — при path-параметрах;
   `422` — при теле запроса или query-параметрах. Тела запросов — именованные схемы.
4. **RBAC в контракте:** `x-required-roles` (роли) и `x-rbac-action` (строки `RBAC_MATRIX.md`).
   Роли операции ⊆ разрешённых матрицей («Нет (чтение)» = только GET); каждое «Да» матрицы
   достижимо хотя бы одной операцией. Object-level проверки остаются в сервисном слое.
5. **Проверки в CI:**
   - `npm run lint:api` — Spectral (`.spectral.yaml`): стиль, именование, правила п. 2–4 (docs-ci);
   - `backend/tests/contract` — роли ↔ матрица, пагинация, ответы, snake_case, поля и ENUM ↔ ORM,
     `maxLength` ≤ `VARCHAR(n)` (backend-ci);
   - `npm run test:mock` — Prism + клиент `web-shared`: 401, 200 `{items, meta}`, 422 (docs-ci);
   - `scripts/check_api_breaking.sh` — `oasdiff breaking` против базовой ветки PR (docs-ci).
6. **Mock:** `npm run mock` — Prism на `http://localhost:4010` (есть в `servers`), проверяет токен
   и валидирует запросы по контракту. Клиенты используют типы `web-shared/src/api/schema.ts`,
   генерируемые `npm run gen:api`; синхронность проверяет docs-ci.

## Политика изменений после заморозки
- Допустимо без новой мажорной версии: новые операции, новые необязательные поля запроса,
  новые поля ответа, новые значения в ответах только при явной оговорке в описании.
- Ломающее изменение (удаление/переименование, новое обязательное поле запроса, сужение
  ограничений, смена типа, новое значение ENUM в запросе как обязательное) — только новой
  мажорной версией (`/v2`) с периодом поддержки v1; `oasdiff` блокирует PR.
- Версия: `1.MINOR.PATCH` — MINOR для добавлений, PATCH для описаний. Тег `api-contract-v1`
  ставится на merge-коммит заморозки.
