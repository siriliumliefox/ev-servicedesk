# Класс информационной системы, защита информации и уполномоченные лица

Глава 26, ADR 0030 п. 21; чек-лист 99-З пп. 11, 12, 25. **Не юридическое заключение** — инженерная
подготовка для оператора (ООО «ЕТСавтоГомель») и аттестующей организации.

**Решение владельца (2026-10-19): аттестация системы защиты информации не проводится.** По приказу ОАЦ
№ 66 ввод ИС с реальными ПД в эксплуатацию без аттестата — нарушение; это ASSUMPTION и риск проекта
(чек-лист 99-З п. 25). Документ — на случай, если компания решит аттестовать систему.

## 1. Класс — «3-ин» (проект акта отнесения)
- Обрабатываемые ПД: телефон, VIN, Telegram id, тексты обращений, фото и видео авто, история ТО —
  **неспециальные** (категория «прочие ПД», O3). Биометрия не обрабатывается (фото не используются для
  идентификации — иначе класс «3-бг»).
- ИС **подключена к открытым каналам** (Интернет).
- Итог: **3-ин** («ИС, где обрабатываются ПД, кроме специальных, подключённая к открытым каналам», O1).

Проект акта: «Информационная система EV-ServiceDesk ООО «ЕТСавтоГомель» (сервис поддержки владельцев
электромобилей: мобильное приложение, кабинеты инженера и администратора, серверная часть) отнесена к
классу 3-ин. Обрабатываются персональные данные клиентов (номер телефона, VIN, сведения об обращениях),
специальные персональные данные не обрабатываются; система подключена к сети Интернет.» Подписывает
руководитель оператора.

## 2. Что дальше по приказу № 66 (если аттестовывать)
Акт класса → техническое задание на СЗИ (класс, требования приложения 3, требования, реализованные у
провайдера по договору — п. 15 Положения) → проектирование → создание СЗИ → **аттестация** (своё
подразделение с профильной подготовкой или организация с лицензией ОАЦ на ТКЗИ) → аттестат на 5 лет →
сведения в ОАЦ не позднее 10 дней. Облако Timeweb (Россия) аттестата ОАЦ нет — для аттестации в РБ
понадобится переезд к провайдеру РБ с аттестованным облаком (hoster.by, beCloud, A1 Digital, ActiveCloud —
справка главы 26) — тот же вывод, что по Указу № 60 (O4).

## 3. Требования приложения 3 (класс 3-ин) и что сделано
«+» обязательное, «±» рекомендуемое (по O1). Статус: **да** — реализовано в проекте; **провайдер** —
мера инфраструктуры хостинга; **орг.** — организационная мера оператора; **нет** — не сделано.

| Требование | Обяз. | Статус | Где |
|---|---|---|---|
| Журналы событий ИБ, централизованный сбор, хранение ≥ 1 года (п. 1.2, 1.3) | + | да | `app.security` → Loki, поток 365 дней (ADR 0030 п. 15) |
| Идентификация и аутентификация, управление учётными записями (раздел 3, п. 3.6) | + | да | SMS-код (клиент), пароль argon2id + политика (сотрудник), RBAC, блокировка, отзыв сессий (ADR 0013, 0029) |
| Шифрование при передаче по открытым каналам сертифицированными средствами (п. 5.1) | + | частично | TLS 1.2/1.3 (несертифицированные в РБ средства); сертифицированный канал управления — вопрос аттестации |
| Шифрование при хранении (п. 5.2) | ± | частично | бэкапы — AES-256 pgBackRest (несертифицированное); диски — нет (провайдер не предлагает) |
| Резервное копирование (п. 6.4) | + | да | pgBackRest, PITR 14 дней, проверка восстановления (ADR 0030 п. 9) |
| Межсетевой экран, сегментация, отдельная сеть управления (пп. 7.9, 7.11–7.13) | + | частично | firewall Timeweb + ufw (22/80/443); мониторинг и Grafana — только 127.0.0.1 и SSH-туннель; отдельной сети управления нет |
| Обнаружение и предотвращение вторжений (п. 7.16) | + | нет | fail2ban (SSH) — не IDS/IPS; провайдер — не известно |
| Контроль внешних подключений (п. 7.12) | + | частично | только ключи SSH, forced command деплоя |
| Журнал DNS-запросов ≥ 1 месяца (п. 7.19) | + | нет | — |
| Анализ защищённости, пентест (п. 7.17) | ± | частично | ZAP, автотесты RBAC/IDOR (ADR 0029); внешний пентест — глава 28 |
| EDR, DLP (пп. 7.15, 7.18) | ± | нет | — |
| Обновления безопасности | + | да | unattended-upgrades, dependabot, dependency-audit в CI |

## 4. Уполномоченные лица (99-З ст. 7, чек-лист п. 11) — отложено владельцем
| Лицо | Что обрабатывает | Страна | Договор поручения |
|---|---|---|---|
| Timeweb Cloud (ВМ, S3) | все ПД системы, бэкапы (зашифрованы) | Россия (ЕАЭС — перечень НЦЗПД, приказ № 14) | нужен |
| A1 «Smart-рассылка» | номер телефона, текст SMS (код, «данные удалены») | Беларусь | нужен |
| Google (FCM), Apple (APNs) | push-токен, текст уведомления без ПД | США (не в перечне) | условия сервиса; основание трансграничной передачи — согласие (глава 27) |
| Telegram (алерты, привязка) | алерты — без ПД; привязка — `telegram_id` клиента | вне ЕАЭС | алерты — не ПД; привязка — глава 27 |
| healthchecks.io (dead-man) | только сигнал «цепочка жива», без ПД | ЕС | не требуется |

Обязательные пункты договора поручения (99-З ст. 7; «Стандартные положения» НЦЗПД): цели и перечень
действий с ПД, обязанность конфиденциальности, меры защиты по ст. 17, привлечение субподрядчиков только с
согласия оператора, удаление или возврат ПД по окончании, уведомление оператора о нарушениях
(для срока 3 рабочих дня — [INCIDENT_PD.md](../runbooks/INCIDENT_PD.md)).
